# HSGDet 论文分享草稿

> 论文：**Prompt-Free Unknown Label Generation for Open World Detection in Remote Sensing**  
> 作者：Abdullah Azeem, Ruisheng Wang, Qingquan Li, Abubakar Siddique  
> 会议：CVPR 2026，pp. 34662–34672  
> 分享建议时长：20–25 分钟（报告 18–20 分钟，讨论 5 分钟）

## 0. 一句话结论

HSGDet 把遥感开放世界检测从“发现一个不知道是什么的未知目标”，推进到“在不接收测试时提示词的条件下，为未知目标生成语义表示并扩展类别图谱”：它用**层级语义图**限定语义搜索空间，用**场景上下文**引导从粗到细的类别路径，再通过 CR2T 将未知区域映射到 CLIP 文本空间。

对 GeoNexus-RSD 而言，这篇论文最重要的价值不是提供可直接横向比较的 DIOR-R 数字，而是独立验证了两个相同的结构先验——**taxonomy hierarchy** 与 **scene context**——在遥感开放世界识别中的有效性。两者的任务边界不同：HSGDet 面向开放世界未知发现与命名；GeoNexus-RSD 面向闭集/给定类别空间中的层级—上下文视觉语言提示与旋转检测。

## 1. 分享开场：为什么值得读？（约 2 分钟）

### 1.1 一个容易被混淆的问题

开放词汇检测（OVD）和开放世界检测（OWOD）解决的并不是同一个问题：

| 范式 | 测试时给定类别词？ | 能否发现未给定类别？ | 能否给未知目标命名？ |
|---|---:|---:|---:|
| 闭集检测 | 固定类别集 | 否 | 不涉及 |
| OVD | 是 | 通常不能主动发现未提示目标 | 仅识别被提示类别 |
| OWOD | 否 | 是 | 通常只输出 `unknown` |
| 统一 OW-OVD | 通常仍依赖提示、属性或外部模型 | 是 | 部分方法可辅助命名 |
| **HSGDet** | **部署时无需外部提示** | **是** | **生成语义嵌入并转为可读标签** |

### 1.2 论文抓住的缺口

现有 OWOD 可以回答“这里有一个未知物体”，但不能回答“它大概是什么”；现有 OVD 可以根据输入词汇找目标，但无法自主发现用户没有想到、也没有输入的类别。HSGDet 的目标是同时完成：

1. 检测已知目标；
2. 将低置信区域识别为未知目标；
3. 不依赖部署时外部提示或 LLM，为未知目标生成语义表示；
4. 将稳定出现的新类别加入层级图，实现词汇表扩展。

**开场话术：**

> 如果一张灾后遥感图像中出现训练集从未见过的设备，传统检测器会漏掉它，开放词汇检测器需要我们先猜到名称并输入提示，而开放世界检测器最多说“这里有未知目标”。HSGDet 想再走一步：让模型自己发现、自己形成语义表示，并把新类别挂到已有知识结构中。

## 2. 任务定义与核心挑战（约 2 分钟）

给定图像 $I$ 和训练阶段的已知类别集合 $K$，模型需要输出：

- 已知目标：
  \[
  \hat D_{known}=\{(b_i,\hat y_i)\},\quad \hat y_i\in K;
  \]
- 未知目标：
  \[
  \hat D_{unknown}=\{(b_j, unknown)\};
  \]
- 未知目标的新语义表示/标签 $\ell_{new}$；
- 扩展后的类别集合：
  \[
  K'=K\cup\{\ell_{new}\}.
  \]

遥感场景中的额外难点包括：

- 小目标、密集分布和遮挡导致区域外观不充分；
- 不同细粒度类别外观相近，例如不同用途车辆；
- 类别语义依赖空间共现，例如油罐车—炼油设施、货车—仓储区；
- 未知类别不能依靠一个固定的平坦分类头直接表示。

## 3. 总体框架（约 3 分钟）

HSGDet 以 Deformable DETR 为基础，使用冻结的 CLIP ViT-B/32 视觉编码器提取多尺度特征。Transformer 解码器维护 300 个 object queries，共 4 层；每层依次进行自注意力、可变形空间注意力、层级图注意力与前馈网络。

可以把整体流程概括为：

```text
遥感图像
   ↓
冻结的 CLIP 视觉编码器 → 多尺度图像特征
   ↓
Deformable DETR queries
   ↓
场景上下文 token 聚合所有 query 的共现信息
   ↓
DHGA：在层级语义图中由粗到细导航
   ├─ 高置信 → 已知类别 + 检测框
   └─ 低置信 → 未知目标 → CR2T
                              ↓
              视觉 query + 场景上下文 + 最近层级父节点
                              ↓
                  新的 CLIP 空间语义嵌入
                              ↓
              缓冲、聚类、注册为新的图节点
```

两个核心模块是：

- **DHGA（Deformable Hierarchical Graph Attention）**：解决“目标在语义图的哪条路径上”；
- **CR2T（Context-Aware Region-to-Text）**：解决“被判为未知后，怎样形成可用的语义表示”。

## 4. 模块一：层级语义图与 DHGA（约 4 分钟）

### 4.1 层级语义图

图 (G=(V,E)) 来自 WordNet 的 `IS-A` 分类关系。每个节点 (v) 有两类表示：

- CLIP 文本嵌入 (t_v\in\mathbb{R}^d)，用于视觉—语义对齐；
- 可学习的 key embedding (e_v\in\mathbb{R}^d)，用于 query 相关的节点选择。

边表示父子关系，例如：

```text
Transportation
├── Aircraft
│   ├── Commercial Airliner
│   └── Military Fighter
└── Ship
    ├── Cargo Ship
    └── Naval Vessel
```

平坦分类是在所有叶子类别间一次决策；层级分类则先判断粗粒度父类，再逐步进入子类，因此能把细粒度错误限制在相近的语义分支内。

### 4.2 Scene Context Token（SCT）

一个可学习的场景 token (c) 对当前层全部 object queries 做交叉注意力，汇聚共现关系：

\[
c_{new}=\operatorname{CrossAttn}(c_{prev},q_i,q_i),
\]

\[
\tilde q_i=q_i+c_{new}.
\]

这里的关键不是给每个目标裁剪局部背景，而是把同一幅图中全部候选目标的关系压缩到共享场景表示，再反向调制每个 query。

### 4.3 稀疏节点采样与图导航

对场景增强后的 query $\tilde q_i$，模型先与所有节点 key 计算相关性，再取 Top-K：

\[
\delta_{i,v}=\tilde q_i^T e_v,
\qquad
S_i=\operatorname{TopK}(\operatorname{softmax}(\delta_i),K).
\]

随后使用节点的 CLIP 文本嵌入进行注意力融合：

\[
\beta_{i,v}=\operatorname{softmax}
\left(\frac{\tilde q_i^T t_v}{\sqrt d}\right),
\]

\[
q_i^{next}=q_i+\sum_{v\in S_i}\beta_{i,v}t_v.
\]

早期解码层偏向宽泛的父节点，随着 query 的视觉细节逐层增强，注意力逐渐转向细粒度子节点。这个“由粗到细”不是手工规划的硬路径，而是由逐层 query refinement、层级路径监督和场景偏置共同形成。

最终若

\[
\max_v\beta_{i,v}<\tau_{unk},\qquad \tau_{unk}=0.4,
\]

该 query 被视为未知并送入 CR2T。

**分享时应强调：**场景上下文不是独立的后处理模块，而是进入图节点采样与注意力计算，直接改变层级路径选择。

## 5. 模块二：CR2T 与词汇扩展（约 4 分钟）

### 5.1 未知语义嵌入生成

即使一个 query 对所有已知叶子类别的置信度都低，最高响应节点仍能提供一个粗粒度父类。模型选择：

\[
v_p=\arg\max_{v\in S_i}\beta_{i,v}.
\]

CR2T 再融合三种信息：

1. 最终层的视觉 query (q_i^{final})；
2. 场景上下文 (c)；
3. 最近父节点的文本嵌入 (t_{v_p})。

\[
t_{new}=f([q_i^{final};c;t_{v_p}]),
\]

其中 (f) 是三层 MLP。输出 (t_{new}) 位于 CLIP 嵌入空间，可作为新类别的连续语义表示。

### 5.2 如何训练一个“未知类别生成器”

训练时没有真正未知类别的标签可直接监督，因此作者随机遮蔽 30% 已知类别，将其模拟成 pseudo-unknown。CR2T 损失同时要求：

- 预测嵌入靠近被遮蔽类别的真实 CLIP 文本嵌入；
- 预测嵌入远离同一父类下的 sibling 类别，避免语义塌缩。

总损失为：

\[
\mathcal L=\mathcal L_{det}
+0.5\mathcal L_{hier}
+0.3\mathcal L_{CR2T}.
\]

其中检测损失只包含 L1 与 GIoU 框回归；分类功能由层级图导航承担。

### 5.3 如何防止一次误检污染词汇表

模型并不立刻把每个未知样本注册为新类，而是采用 buffer-and-cluster：

- 缓存未知嵌入；
- 当 $M=5$ 个样本两两余弦相似度高于 $\tau_{sim}=0.7$ 时建立新节点；
- 新节点取簇内平均语义嵌入；
- 继承父节点的 key，并挂到预测父节点下；
- 后续图像可立即使用该节点进行识别。

为了给人输出可读名称，论文还会在预测父节点的子类候选中，对 CLIP 文本嵌入做层级约束的最近邻检索。

## 6. 实验设计与主要结果（约 4 分钟）

### 6.1 数据集与协议

作者使用 DOTA-v2、FAIR1M、DIOR 和 COCO：

- DOTA-v2、COCO：四阶段增量式 OWOD 协议；
- FAIR1M、DIOR：固定 known/unknown 划分的单阶段协议；
- 指标：Known mAP（K-mAP）、Unknown Recall（U-R）、Wilderness Impact（WI，越低越好）以及部分表格中的 A-mAP。

### 6.2 DOTA-v2 Task 1 消融

| DHGA | SCT | CR2T | K-mAP ↑ | U-R ↑ | WI ↓ |
|---:|---:|---:|---:|---:|---:|
| × | × | × | 44.7 | 20.5 | 14.3 |
| ✓ | × | × | 48.9 | 28.0 | 11.2 |
| ✓ | ✓ | × | 52.1 | 33.8 | 8.4 |
| ✓ | ✓ | ✓ | **54.8** | **41.2** | **5.8** |

这张表是整篇论文最能支撑方法动机的结果：

- 层级图导航提升 U-R 7.5 个点；
- 加入场景 token 后再提升 5.8 个点；
- 完整 CR2T 后再提升 7.4 个点；
- 完整模型相较基线 K-mAP +10.1、U-R +20.7，WI 从 14.3 降到 5.8。

### 6.3 场景信息在哪些类别最有效？

补充材料显示，场景依赖越强的类别，SCT 增益越大：

| 类别 | 无 SCT | 有 SCT | $\Delta$ mAP | 场景依赖 |
|---|---:|---:|---:|---|
| large vehicle | 46.8 | 58.9 | +12.1 | 很高 |
| storage tank | 46.5 | 58.1 | +11.6 | 很高 |
| small vehicle | 52.3 | 59.8 | +7.5 | 中等 |
| helicopter | 58.2 | 63.4 | +5.2 | 中等 |
| ship | 68.4 | 70.1 | +1.7 | 低 |
| bridge | 71.2 | 72.3 | +1.1 | 低 |
| tennis court | 80.1 | 81.0 | +0.9 | 低 |

这比只报告总体指标更有说服力：上下文并非对所有类别平均“加分”，而是主要帮助外观不足以消歧的类别。

### 6.4 与 OWOD 方法比较

论文报告：

| 数据集/阶段 | HSGDet K-mAP | HSGDet U-R | HSGDet WI |
|---|---:|---:|---:|
| DOTA-v2 Task 1 | 54.8 | 41.2 | 5.8 |
| FAIR1M | 52.4 | 38.5 | 6.2 |
| DIOR | 59.3 | 42.8 | 5.2 |

相较表中最强对手 SkySense-O，HSGDet 在 FAIR1M 上 K-mAP +6.6、U-R +9.9；在 DIOR 上 K-mAP +6.4、U-R +9.2。

**必须准确说明：论文用的是 DIOR，而不是 DIOR-R。** 因此该行不能直接进入 GeoNexus-RSD 的 DIOR-R 旋转检测比较表；它只能作为同源数据语义与开放世界任务的背景证据。

## 7. 这篇论文真正做对了什么？（约 2 分钟）

### 7.1 结构先验与任务需求匹配

HSGDet 没有把“未知命名”简化为全词表暴力检索，而是先找父类、再在局部分支形成细粒度语义；这降低了开放空间中的搜索难度。

### 7.2 上下文介入了决策过程

场景 token 不只是拼接到最后的分类器，而是影响每层的节点选择和语义融合。因此“机场—飞机”“炼油设施—油罐车”等共现关系能够改变推理路径。

### 7.3 将单样本命名变成持续验证

buffer-and-cluster 用重复观测约束新类别注册，承认开放世界中的单次预测不可靠，也使词汇扩展更接近实际部署过程。

### 7.4 消融与失败案例较完整

补充材料分析了 SCT 注入层、聚类阈值、类别级上下文收益和 150 个失败案例。主要失败来源是严重遮挡（37.2%）和小于等于 32 px 的微小目标（30.4%）。

## 8. 批判性阅读：需要追问的地方（约 3 分钟）

### 8.1 “Prompt-free”不等于“无语言先验”或“无限开放词汇”

模型部署时确实不要求用户输入 prompt，也不调用外部 LLM；但它仍依赖：

- 预先构建的 WordNet `IS-A` 层级；
- CLIP 视觉—文本空间；
- 已有节点的 CLIP 文本嵌入；
- 为输出人类可读名称而进行的候选类别文本嵌入近邻检索。

因此更准确的表述是：**prompt-free at deployment under a pretrained semantic space**，而不是从完全无词表状态中自由生成字符串标签。

### 8.2 “生成文本嵌入”与“生成新名称”仍有距离

CR2T 生成的是连续向量，而人类可读标签来自预先编码候选名称的最近邻映射。如果真实新类别不在候选名称集合中，模型是否还能输出正确且稳定的名字，论文没有充分回答。

### 8.3 伪未知训练与真正未知之间存在分布差异

训练时通过遮蔽已知类别学习 CR2T，这些 pseudo-unknown 仍来自训练数据分布和已有层级。真正新类别可能没有合适父节点，或者与已知类别存在跨分支关系，此时泛化能力仍需更严格验证。

### 8.4 动态扩展的长期稳定性尚未充分展示

聚类建立的新节点继承父节点 key embedding。随着节点持续增加，可能出现：

- 相近类别重复建点；
- 早期父节点错误被固化；
- 图规模增长后 Top-K 路由漂移；
- 新旧类别间灾难性干扰。

论文展示了扩展机制和短期指标，但没有长期流式部署曲线。

### 8.5 与旋转遥感检测的关系有限

论文列出 DOTA-v2、FAIR1M 和 DIOR，但没有报告 DIOR-R，也没有给出可与当前旋转检测协议直接对齐的 DIOR-R AP50。因此它是结构思想与开放世界范式上的强邻近工作，不是 GeoNexus-RSD 的直接数值 comparator。

### 8.6 文中有一处数字表述需谨慎引用

主文 Table 2 的 Full CR2T 行列出 Semantic Coherence 为 0.82，但同页文字、30% masking 行以及补充材料对应表使用 0.84。分享中建议只引用一致的 Text Alignment 0.79 和 U-R 41.2，或明确指出该排版/报告不一致。

## 9. HSGDet 与 GeoNexus-RSD 的关系（约 3 分钟）

| 维度 | HSGDet | GeoNexus-RSD |
|---|---|---|
| 任务 | 开放世界发现、未知命名、词汇扩展 | 给定类别空间下的遥感旋转检测与视觉语言提示增强 |
| 核心问题 | 未知目标怎样被发现并获得语义 | 已有类别怎样利用层级与上下文提升细粒度判别 |
| 层级作用 | 约束未知类别的粗到细图导航 | 组织类别语义与提示/分类关系 |
| 上下文作用 | 调制图路径和未知语义生成 | 调制场景相关的类别评分/提示表示 |
| 语言依赖 | WordNet + CLIP，部署时无用户 prompt | RemoteCLIP/类别提示，类别空间预先给定 |
| 输出空间 | 可动态加入新语义节点 | 闭集或预定义词汇中的类别输出 |
| 检测协议 | OWOD；论文为 DIOR 而非 DIOR-R | DIOR-R 等旋转检测协议 |

### 9.1 可以如何定位我们的贡献

建议在 TGRS Related Work 中这样表达：

> Recent open-world remote-sensing detection has independently shown that hierarchical taxonomy navigation and scene-conditioned reasoning are effective for discovering and semantically grounding unknown objects. HSGDet uses these priors to synthesize unknown-category embeddings and expand its vocabulary without test-time prompts. In contrast, GeoNexus-RSD studies how hierarchy- and context-aware vision-language prompting improves fine-grained oriented detection within a predefined category space. The two methods therefore share structural priors but address complementary open-world and closed-set recognition regimes.

对应中文：

> 最新的遥感开放世界检测工作已经独立表明，层级类别导航与场景条件推理有助于发现未知目标并赋予其语义。HSGDet 利用这两类先验，在测试时无需外部提示即可合成未知类别嵌入并扩展词汇表。与之不同，GeoNexus-RSD 研究的是在预定义类别空间内，层级—上下文视觉语言提示如何提升细粒度旋转检测。因此，两者共享结构先验，但分别面向互补的开放世界与闭集识别问题。

### 9.2 对后续研究最直接的启发

1. **把层级从辅助损失升级为路由结构。** HSGDet 的收益说明，层级关系不仅可做正则项，还可直接控制分类候选与语义路径。
2. **针对上下文依赖类别做分组评估。** 除总体 AP 外，可按强/弱上下文依赖类别报告增益，验证场景模块是否真的在消歧。
3. **分析父节点错误传播。** HSGDet 的失败案例表明，层级父类预测错误会直接污染下游语义；GeoNexus-RSD 也应检查层级错误是局部 sibling confusion 还是跨分支错误。
4. **保持任务边界。** 不应因为 HSGDet 相邻就把当前路线扩展成完整 OWOD；它首先用于强化论文动机、相关工作定位和分析设计。

## 10. 建议的 PPT 页序

1. 标题页：论文信息 + 一句话贡献
2. 问题页：闭集、OVD、OWOD、HSGDet 四种范式
3. 动机页：为什么遥感中的未知目标需要层级与场景
4. 总体架构页：使用原文 Figure 2，并标出 DHGA/CR2T

## 11. 结束页：三个 Take-away

1. HSGDet 的核心不是简单增加一个未知类，而是把**发现—语义形成—词汇扩展**连成闭环。
2. **层级提供搜索结构，场景提供路径条件**；两者结合是它超越平坦 OWOD/OVD 的关键。
3. 它为 GeoNexus-RSD 的两类结构先验提供了强邻近证据，但其 **DIOR 结果不能当作 DIOR-R 旋转检测对比数字**。

**结束话术：**

> 我认为这篇论文最值得带走的观点是：开放世界识别不能只靠扩大词表，必须给语义搜索加入结构。层级告诉模型应该向哪里细分，场景告诉模型当前应该走哪条分支。HSGDet 用这个组合解决未知命名；GeoNexus-RSD 则可以在预定义类别的旋转检测中检验同一组先验如何改善细粒度判别。

## 12. 可用于现场讨论的问题

1. 生成 CLIP 空间中的向量，再通过候选词近邻转成名称，能否称为真正的“unknown label generation”？
2. 如果未知类别不在 WordNet 分支或候选名称中，HSGDet 会生成什么？
3. 场景共现会不会把数据集偏差固化，例如“飞机一定在机场附近”？
4. 动态图扩展长期运行后，如何合并重复节点或纠正错误父节点？
5. 若把该思想迁移到旋转检测，层级导航应作用于分类头、query refinement，还是提示嵌入？
